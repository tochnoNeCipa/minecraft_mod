# RoboHelper

Модульный робот-помощник для **Minecraft Java Edition 1.20.1 / Fabric**.
Текущая версия — **1.1.0**, идентификатор `robohelper`, пакет `com.robohelper`.

## Что работает

Робот создаётся корпусом, запоминает владельца, хранит предметы, заряжается топливом
и поддерживает режимы WORK / IDLE / FOLLOW. Есть рабочая зона и возвращение к её
центру, GUI с 22 слотами, кнопками и полосой энергии, ручная выгрузка и сохранение NBT.
Предметы профессий и рабочие модули ещё не реализованы.
Подробный план и результаты каждого этапа: [docs/PROGRESS.md](docs/PROGRESS.md).

## Установка и проверка в игре

1. Установите Minecraft Java 1.20.1, Fabric Loader 0.16.14 или новее для этой версии
   и Fabric API 0.92.2+1.20.1.
2. Положите **robohelper-1.1.0.jar** и Fabric API в папку `mods`. Предыдущий JAR
   RoboHelper замените: одновременно должна оставаться только одна версия мода.
3. Во вкладке творческого режима **RoboHelper** возьмите **Корпус робота**.
   При включённых командах: `/give @s robohelper:robot_body`.
4. Нажмите корпусом по верхней грани блока, над которым свободны два блока.
   В выживании тратится один корпус, в творческом режиме он остаётся в руке.
5. ПКМ пустой рукой по своему роботу открывает GUI. Чужой игрок получает
   сообщение «Это не ваш робот» и не может управлять контейнером.

Рецепт корпуса на верстаке:

```text
железо   редстоун  железо
железо   сундук    железо
железо   железо    железо
```

## Управление

- **18 ячеек хранения** принимают любые предметы. Shift переносит стопку между
  роботом и игроком. Топливо сначала направляется в свой слот.
- **Слот топлива** принимает предметы с ненулевым временем горения. Можно заправить
  робота также ПКМ топливом. Уголь даёт 1600 энергии, ёмкость — 6400.
- **3 слота модулей** принимают только предметы профессий, по одному. Одинаковую
  профессию нельзя вставить дважды, включая обмен с хотбаром и перетаскивание.
  Эти предметы появятся на следующем этапе; сейчас слоты остаются пустыми.
- **Режим** переключается WORK → IDLE → FOLLOW → WORK. Новый робот находится в IDLE.
  FOLLOW бесплатен: робот начинает идти дальше 6 блоков, останавливается около 3,
  а дальше 24 ищет безопасное место для телепортации рядом с владельцем в том же
  измерении. WORK без профессий ожидает либо возвращается к центру зоны.
- **Зона здесь** переносит центр в текущую позицию робота. Радиус — 15 блоков
  по горизонтали и ±8 по вертикали.
- **Выгрузить** переносит 18 ячеек хранения игроку, излишек выпадает на землю.
  Топливо и модули остаются в роботе. То же действие: **Shift + ПКМ пустой рукой**.
  Переполнение сохраняется и в творческом режиме.
- **Направление** пока недоступно без модуля шахтёра. При его наличии кнопка
  запоминает сторону света, в которую смотрит робот.
- **Полоса энергии** зелёная выше 25 %, жёлтая от более 5 % до 25 %, красная при
  5 % и ниже. Наведите мышь, чтобы увидеть точное значение. Строка статуса показывает
  ожидание, следование, возвращение, недостаток энергии или отсутствие модулей.

Топливо с ценностью больше 6400 (например, угольный блок) не сгорает: по буквальному
правилу ТЗ в хранилище должно помещаться всё количество энергии без потерь.
Ходьба в WORK расходует 1 энергию за 20 тиков движения; при ≤320 работа
останавливается и раз в 5 секунд подаётся сигнал дымом и звуком. FOLLOW и ожидание
не расходуют энергию.

Владелец, слоты, здоровье, энергия, режим, зона и направление сохраняются в NBT.
Сохранения предыдущих частей поддерживаются. Экран закрывается при удалении от
робота или его гибели; предмет на курсоре возвращается игроку либо выпадает,
если в инвентаре нет места.

## Разработка и сборка

Нужны **JDK 17**, доступ к Maven Central, Gradle, `maven.fabricmc.net` и серверам
загрузки Minecraft. Gradle устанавливать отдельно не требуется: используется
проверяемый по SHA-256 Gradle Wrapper 8.6. Версии закреплены в `gradle.properties`.

Из корня проекта, с `JAVA_HOME`, указывающим на JDK 17:

```sh
./gradlew build --no-daemon
./gradlew runGametest --no-daemon
./gradlew runClient
./gradlew runServer --args=nogui
```

На Windows используйте `gradlew.bat` вместо `./gradlew`.
Результат: `build/libs/robohelper-1.1.0.jar`. JAR с `-sources` — исходники,
он не нужен в папке `mods`. При выпуске следующей версии изменяется `mod_version`:
она автоматически попадает в имя JAR и в `fabric.mod.json`.

Первый запуск обычного сервера генерирует `run/eula.txt`. Прочитайте EULA Minecraft
и, если согласны, установите `eula=true`. GameTest запускает отдельный автоматический
тестовый сервер и завершает его после проверок.

Общая логика и контейнер находятся в `src/main`, рендер и экран — в `src/client`.
Клиент и сервер синхронизируют GUI стандартными слотами, свойствами и пакетами кнопок
Minecraft, без собственных сетевых пакетов. Сервер повторно проверяет владельца,
мир, расстояние, допустимость предметов и доступность кнопок.

## Проверки версии 1.1.0

`./gradlew build runGametest --no-daemon` проходит **34/34** обязательных серверных
проверок без пропусков. Отчёт: `build/gametest-results.xml`. Покрыты создание,
сохранение, энергия, навигация и операции GUI, включая отказ чужому игроку,
дубликаты профессий, переполнение и закрытие с предметом на курсоре.
Тестовые классы и предметы из `src/gametest` не включаются в выпускаемый JAR.
GitHub Actions выполняет сборку и серверные проверки.

Отрисовка русского GUI дополнительно просмотрена в настоящем клиенте Minecraft
на виртуальном экране с тестовыми данными, без игрового мира. Это проверка внешнего
вида, а не ручная сетевая игровая сессия. Полная приёмка Т-01…Т-28, профессии,
замеры производительности и ручная проверка перезапуска мира ещё впереди.
