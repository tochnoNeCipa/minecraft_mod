# RoboHelper

Модульный робот-помощник для **Minecraft Java Edition 1.20.1 / Fabric**.
Курсовой проект. Идентификатор мода: `robohelper`, пакет: `com.robohelper`.

## Состояние

Реализована базовая сущность робота: создание из корпуса, владелец, атрибуты,
22 слота, сохранение NBT и выпадение содержимого при гибели. Есть гуманоидный
рендер, текстура, рецепт корпуса и вкладка творческого режима.
Добавлены энергия, автоматическая зарядка топливом, режимы WORK / IDLE / FOLLOW,
рабочая зона и возвращение к её центру. GUI и профессии ещё не реализованы.
План этапов и результаты проверок: [docs/PROGRESS.md](docs/PROGRESS.md).

## Требования

- JDK 17 (именно комплект разработки, а не только JRE).
- Доступ к Maven Central, Gradle, `maven.fabricmc.net`, серверам загрузки Minecraft.
- Gradle устанавливать отдельно не нужно: используется Gradle Wrapper 8.6.

## Команды

Из корня репозитория, с `JAVA_HOME`, указывающим на JDK 17:

```sh
./gradlew build --no-daemon
./gradlew runGametest --no-daemon
./gradlew runClient
./gradlew runServer
```

На Windows: `gradlew.bat build`, `gradlew.bat runClient`, `gradlew.bat runServer`.
Результат сборки: `build/libs/robohelper-1.0.0.jar`.
Файл с суффиксом `-sources` предназначен для просмотра исходников.

При первом запуске сервера необходимо прочитать EULA Minecraft и, если вы с ней
согласны, установить `eula=true` в сгенерированном `run/eula.txt`.
Для игры нужен графический клиент Minecraft; успешная серверная сборка сама по
себе не подтверждает работу интерфейса и графики.

## Архитектура

Общая игровая логика располагается в `src/main`, клиентские классы — в
`src/client`. Такое разделение помогает не загружать графические классы на
выделенном сервере. Версии зависимостей зафиксированы в `gradle.properties`.

## Проверка текущей версии в игре

1. Установите Fabric для Minecraft 1.20.1 и Fabric API 0.92.2+1.20.1.
2. Поместите `build/libs/robohelper-1.0.0.jar` в папку `mods` профиля.
3. Во вкладке творческого режима **RoboHelper** возьмите **Корпус робота**.
   Альтернатива при включённых командах: `/give @s robohelper:robot_body`.
4. Нажмите корпусом по верхней грани блока, над которым свободны два блока.
   Появится робот; в выживании расходуется один корпус, в творческом — нет.
5. ПКМ пустой рукой показывает владельцу здоровье, энергию и режим робота. Другой игрок получает
   сообщение «Это не ваш робот». Экран инвентаря пока не открывается.
6. Выйдите из мира и зайдите снова: робот должен остаться на месте.

Корпус также можно скрафтить на верстаке:

```text
железо   редстоун  железо
железо   сундук    железо
железо   железо    железо
```

Робот принимает топливо по ПКМ владельца (уголь, доски и другие предметы из
FuelRegistry), автоматически заряжается до 6400 и показывает запас по ПКМ пустой
рукой. Уголь даёт 1600 энергии. Предмет с ценностью больше 6400 (например, угольный
блок) остаётся в слоте: по правилу ТЗ он не сгорает с потерей лишней энергии.

После создания робот находится в IDLE. До появления GUI режим можно проверить
ванильной командой при включённых читах, стоя возле нужного робота:

```mcfunction
/data merge entity @e[type=robohelper:robot,sort=nearest,limit=1,distance=..8] {Mode:"FOLLOW"}
```

FOLLOW не требует энергии: робот начинает идти при удалении более 6 блоков,
останавливается около 3 блоков, а дальше 24 блоков пытается телепортироваться
на свободную безопасную опору рядом с владельцем. Владелец должен находиться
в том же измерении. Безопасного места нет — робот пробует обычную навигацию
и позднее повторяет попытку; слепой телепортации в стену или на магму нет.

Аналогично замените `FOLLOW` на `IDLE` (ожидание) или `WORK` (работа). У команд
`/data` административные права: это временный способ проверки до добавления
экрана владельца, а не обычное управление игрока.

Центр зоны запоминается при появлении, радиус — 15 блоков по горизонтали
и ±8 по вертикали. В WORK робот вне зоны сначала возвращается к её центру.
На это нужна энергия выше 320, ходьба расходует 1 единицу за 20 тиков движения.
При 320 и ниже движение по рабочей задаче останавливается; раз в 5 секунд
подаётся сигнал дымом и звуком. FOLLOW и ожидание не расходуют энергию.
Без профессий WORK внутри зоны просто ожидает. Профессии появятся позже.

Энергия, режим, центр и радиус сохраняются в NBT. Сохранения части 2 поддерживаются:
без новых полей робот загружается в IDLE с нулевой энергией и центром в текущей позиции.

## Серверные интеграционные тесты

`./gradlew runGametest --no-daemon` запускает отдельный автоматический GameTest-сервер
без графики и завершает его после проверок. Отчёт: `build/gametest-results.xml`.
Тестируются создание в выживании/творческом режиме, отказ при недостатке места,
NBT всех слотов, владелец и дистанция доступа, фильтры слотов, выпадение предметов
и защита от падения до 5 блоков. Это отдельные проверки текущего этапа, а не полная
приёмка Т-01…Т-28. В части 3 добавлены проверки топлива и ёмкости, запрета чужой заправки,
порога энергии, восстановления старых сохранений, границ зоны, настоящего движения
к центру, бесплатного следования, безопасной телепортации и остановки после смены
режима. Текущий результат — **21/21** обязательных тестов без пропусков.
Код и тестовые предметы находятся в `src/gametest` и не попадают
в распространяемый JAR. GitHub Actions запускает сборку вместе с этими тестами.
