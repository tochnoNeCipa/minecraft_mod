# Карта кода для защиты

Все пути ниже указаны относительно `02_ИСХОДНИКИ/проект`.

## Как правильно назвать части мода

У RoboHelper клиент-серверная архитектура Minecraft. Клиент отвечает за
отображение и интерфейс. Сервер выполняет игровые действия и проверяет их
допустимость. В одиночной игре тоже работает встроенный сервер.

`src/main` — общий набор исходников: он содержит серверную логику и общие классы,
которые нужны обеим сторонам. Это не строго отдельная папка «только сервер».
`src/client` содержит классы, которые должны загружаться только клиентом.
Это разделение задано через `splitEnvironmentSourceSets()` в `build.gradle`.

## Пример взаимодействия клиента и сервера

1. Игрок нажимает кнопку режима в `RobotScreen`.
2. Клиент отправляет стандартный пакет нажатия кнопки Minecraft.
3. Серверный `RobotScreenHandler` проверяет доступ и допустимость действия.
4. `RobotEntity` меняет режим; менеджер разрешает соответствующие цели модулей.
5. Слоты и свойства синхронизируются обратно; клиент рисует актуальное состояние.

У проекта нет HTTP-сервера, REST API и веб-страницы как игрового интерфейса.
Для хранения состояния используется NBT Minecraft, а не отдельная СУБД.

## Короткое объяснение архитектуры

«RobotEntity хранит общее состояние. Профессия реализует RobotModule и создаёт
свои задачи Goal. ModuleRegistry создаёт поведение по идентификатору,
ModuleManager подключает его к роботу. Общие уровни, интервалы и расход энергии
вынесены в AbstractModule. Поэтому новая профессия не требует переписывать
основную игровую логику сущности».

Для новой профессии всё равно нужны предмет, регистрация и ресурсы. Формулировка
«один класс» относится к классу поведения, а не ко всему набору файлов мода.

## Что полезно повторить перед защитой

- Интерфейс задаёт контракт; класс реализует поведение. Виртуальные методы дают
  менеджеру возможность работать с разными профессиями через общий тип.
- Goal — задача ИИ, которую Minecraft запускает и останавливает по условиям.
- BFS — обход в ширину через очередь. Лесоруб ищет связную группу брёвен;
  лимит 128 ограничивает стоимость и защищает от слишком большой группы.
- Приоритеты позволяют охране прерывать логистику, а логистике — производство.
- Серверная проверка владельца не даёт другому игроку управлять чужим роботом.
- NBT сохраняет данные сущности и предметов, включая прогресс модулей.
- Тест — проверка определённого сценария. 113 пройденных тестов не означают
  доказанное отсутствие всех возможных ошибок.
