# Приёмка RoboHelper 1.6.1

**113/113 обязательных серверных проверок прошли**, без ошибок и пропусков.

Проверки выполнены в облачной Linux-среде на Minecraft 1.20.1 / Fabric Loader
0.16.14 / Fabric API 0.92.2, Java 17.0.20.1. Результаты относятся к ванильному
проверочному миру с RoboHelper; совместимость с произвольными сборками модов
этим не устанавливается.

## Виды проверок

- Обязательные серверные GameTests: игровые действия, настоящие рецепты,
  навигация, сохранение, энергия и защита владельца. Баланс измеряется в игровых
  тиках: ускоренный GameTest-сервер не используется как секундомер процессора.
- Два настоящих Fabric-клиента на виртуальном X11-экране подключаются к отдельному
  выделенному серверу. Взаимодействие, слоты и кнопки идут обычными сетевыми пакетами.
  Скриншоты RU/EN визуально просмотрены. Это автоматизированная сетевая сессия,
  а не длительное ручное прохождение двумя людьми.
- Сервер полностью завершается с сохранением мира и запускается в новом JVM-процессе.
  Сверяются владелец, здоровье, энергия, режим, зона, направление, все слоты с NBT
  и задание шахтёра, прерванное между блоками головы и ног. После загрузки добыты
  ровно 12 блоков тоннеля: с исходными 12 булыжниками получено 24, без потерь/дублей.
- Дополнительный робот в удалённом чанке действительно выгружается из мира;
  после загрузки появляется новый Java-экземпляр с тем же UUID и данными.
- Нагрузка измеряется на обычном сервере, вне ускоренного GameTest. Измеряется
  весь `RobotEntity.tick`, включая ванильный MobEntity, навигацию и модули.
  `-Drobohelper.profile=true` включает счётчик; по умолчанию он выключен.

Сетевой сервер привязан **только к 127.0.0.1**, использует тестовые имена
ReleaseOwner/ReleaseOther и `online-mode=false`. Проверяется работа протокола и
разграничение двух UUID; вход в Microsoft/Mojang и интернет-соединение не проверяются.
Настройки проверочного сервера не являются рекомендацией для публичного сервера.

## Повторение

```bash
./gradlew build runGametest --no-daemon
./gradlew writeReleaseClasspath -PreleaseChecks --no-daemon
python tools/run-release-checks.py --fresh --display :99
python tools/render-validation.py
```

Нужны Java 17, Python 3, matplotlib для графиков, доступные игровые assets и X11 с
OpenGL (в проверке использованы Xorg dummy и Mesa software rendering). `--display`
выбирает уже работающий экран. Для воспроизведения без рабочего стола пример
конфигурации находится в [tools/xorg-release.conf](../tools/xorg-release.conf):

```bash
Xorg :99 -config "$PWD/tools/xorg-release.conf" -nolisten tcp -noreset -logfile /tmp/robohelper-xorg.log
```

Вторую командную строку запускайте, пока Xorg работает. На компьютере с обычным
экраном можно передать свой `$DISPLAY`. Скрипт запускает тестовые Minecraft-клиенты
и принимает EULA в создаваемом проверочном каталоге; ознакомьтесь с
[EULA Minecraft](https://aka.ms/MinecraftEULA) перед запуском.
`--fresh` удаляет **только** перечисленные `build/release-*` каталоги. Мир `run/world`
и другие сохранения не меняются. Необязательный Gradle-флаг подключает sourceSet
`release`; его классы, entrypoint и проверочные миры не входят в выпускаемый JAR.

После `writeReleaseClasspath` запускайте сценарий до других Gradle-команд: Loom
перегенерирует `launch.cfg` для выбранного набора sourceSet. По окончании скрипт
завершает запущенные им игровые процессы; отдельный Xorg следует остановить самому.

## Перед публичным стабильным выпуском

Остались пробное прохождение на обычном ПК с реальным звуком, длительная проверка
на типичном сервере и совместимость с выбранными сторонними модами. Описанные
контролируемые проверки не заменяют публичное бета-тестирование.
Для публикации на Modrinth владелец должен выбрать лицензию и оформить страницу.
Лицензия на исходники от имени владельца автоматически не назначалась.
